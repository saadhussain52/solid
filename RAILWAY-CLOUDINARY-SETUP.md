# Product catalogue storage

The admin uploads product images directly to Cloudinary using short-lived
signatures generated by the Railway server. Product details and Cloudinary
image URLs are stored in `products.json` on Railway's persistent volume. The
Cloudinary API secret is never sent to the browser.

## Configure Cloudinary

1. Create or sign in to a Cloudinary account.
2. In the Cloudinary console, copy the **Cloud name**, **API Key**, and **API
   Secret** from the account dashboard.
3. In Railway, open the Solids service's **Variables** and add:
   - `CLOUDINARY_CLOUD_NAME`
   - `CLOUDINARY_API_KEY`
   - `CLOUDINARY_API_SECRET`

Keep the API Secret private; only add it to Railway Variables or a local
`.env` file that is not committed.

## Configure Railway product storage

1. Attach a Railway Volume to the service and mount it at `/data`.
2. Add `DATA_DIR=/data` to the service's Railway Variables. Orders and products
   are both saved in this directory.
3. Set `ADMIN_KEY` to a long, random secret in Railway Variables. The same key
   is required when prompted by the admin panel to manage products.
4. Redeploy the service so the new variables and volume are active.

Without a mounted volume, the catalogue may disappear when Railway replaces
the service instance. Without `ADMIN_KEY`, product writes are intentionally
locked.

## Initialize the existing catalogue

Open the admin page on the deployed site after redeploying. Enter the
`ADMIN_KEY` when prompted. If the server has no product catalogue yet, the
admin migrates products saved in that browser to Railway and uploads any
inline product images to Cloudinary. Do not clear that browser's site data
until the first migration completes.

After initialization, uploaded images and product changes are shared with the
storefront on every device. If migration or upload fails, the admin reports an
error and leaves the catalogue uninitialized so it can be retried.
